## 🔄 完整执行流程（超详细版）

### 阶段 1: 战斗初始化 (Initialization Phase)

```csharp
HorizontalBattleFormationManager.Awake()
    └─ HealthBarUIManager.Instance (单例初始化)

AutoBattleAI.Update()
    └─ decisionDelay 定时器触发
        └─ StartBattleSequence() ← 战斗启动入口
            │
            ├─ 1.1 收集参战角色
            │    FindObjectsOfType<CharacterStats>()
            │    └─ allCombatants: List<CharacterStats>
            │
            ├─ 1.2 执行先攻检定 ✨ 关键
            │    HorizontalCombatRules.RollAndSortInitiative(allCombatants)
            │    └─ 循环每个角色:
            │        ├─ dexMod = (dexterity - 10) / 2
            │        ├─ roll = Random.Range(1, 21)
            │        ├─ total = roll + dexMod
            │        └─ 记录 InitiativeEntry(character, total)
            │       按 total 降序排列
            │
            ├─ 1.3 初始化回合数据
            │    initiativeOrder = [...]  (已排序)
            │    currentTurnIndex = 0
            │    isBattleActive = true
            │
            └─ 1.4 开启回合循环
                 StartNextTurn()
                     └─ 设置 turnTimer = 0
```

### 阶段 2: 回合轮询 (Turn Loop Phase)

```csharp
AutoBattleAI.Update() [每帧调用]
    └─ if (isBattleActive && enableAutoBattle)
        └─ if (!isProcessingTurn)
            └─ turnTimer += Time.deltaTime
                └─ if (turnTimer >= decisionDelay)  // 通常 1.0 秒
                    └─ ProcessCurrentTurn() ✨ 回合处理
                        │
                        ├─ 2.1 检查战斗是否结束
                        │     if (IsBattleOver()) EndBattle()
                        │
                        ├─ 2.2 获取当前行动者
                        │     var currentEntry = initiativeOrder[currentTurnIndex]
                        │     var character = currentEntry.character
                        │
                        ├─ 2.3 检查行动能力
                        │     if (!currentEntry.CanAct()) AdvanceToNextTurn()
                        │
                        ├─ 2.4 特殊处理：昏迷状态
                        │     if (character.HasStatusEffect(StatusEffectType.Unconscious))
                        │         character.PerformDeathSaveTick()
                        │
                        ├─ 2.5 AI决策：选择目标
                        │     var chosenAction = DecideBestAction(character)
                        │     └─ action.target: CharacterStats
                        │
                        ├─ 2.6 执行行动 ✨ 核心分发
                        │     ExecuteBattleActionEvent(character, chosenAction, () => {
                        │         currentEntry.MarkAsActed()
                        │         AdvanceToNextTurn()  // 进入下一角色
                        │     })
                        │
                        └─ isProcessingTurn = true
```

### 阶段 3: 行动分发 (Action Dispatch Phase)

```csharp
AutoBattleAI.ExecuteBattleActionEvent(
    CharacterStats attacker,
    BattleAction action,
    System.Action onComplete
)
    │
    ├─ 3.1 获取动画适配器
    │     var attackerAdapter = attacker.GetComponent<DND_CharacterAdapter>()
    │
    ├─ 3.2 判断攻击类型
    │     bool isMeleeAttack = IsCharacterInFrontRow(attacker)
    │     // 前排 = 近战，后排 = 远程
    │
    ├─ 3.3 分支: 近战 vs 远程
    │  ├─ if (isMeleeAttack)
    │  │   attackerAdapter.ExecuteMeleeAttack(
    │  │       target.transform,
    │  │       onAttackHit: () => ProcessAttackHit(...),
    │  │       onComplete: () => onComplete.Invoke()
    │  │   )
    │  │
    │  └─ else
    │      attackerAdapter.ExecuteRangedAttack(
    │          target.transform,
    │          onAttackHit: () => ProcessAttackHit(...),
    │          onComplete: () => onComplete.Invoke()
    │      )
    │
    └─ 3.4 记录行动日志
         GameLog.LogAction(attacker, "对" + target + "发动攻击")
```

### 阶段 4a: 近战攻击流程 (Melee Attack Phase)

```csharp
DND_CharacterAdapter.ExecuteMeleeAttack(
    Transform target,
    System.Action onAttackHit,
    System.Action onComplete
)
    │
    ├─ 4a.1 状态检查
    │  ├─ if (IsTerminalState()) return           // 死亡/昏迷禁止
    │  ├─ if (isAnimating) return                 // 正在动画中禁止
    │  └─ isAnimating = true                      // 上锁
    │
    ├─ 4a.2 计算攻击位置
    │     Vector3 attackPosition = CalculateAttackPosition(target)
    │     // = target.position - direction * animationConfig.attackDistance
    │     // 通常距离目标 1.5 单位
    │
    ├─ 4a.3 开始移动阶段
    │     PlayWalkAnimation()
    │     // SkeletonAnimation.SetAnimation("walk", loop: true)
    │
    ├─ 4a.4 计算移动时长
    │     float moveDistance = Vector3.Distance(position, attackPosition)
    │     float moveDuration = moveDistance / animationConfig.moveSpeed
    │     // 速度通常 2.0 单位/秒
    │
    ├─ 4a.5 执行移动 Tween
    │     currentMoveTween = transform.DOMove(attackPosition, moveDuration)
    │         .SetEase(animationConfig.moveEase)  // OutCubic
    │         .OnUpdate(() => {
    │             // 检查是否已接近目标
    │             if (distance <= 0.1f) {
    │                 transform.position = attackPosition
    │                 currentMoveTween.Kill()
    │                 
    │                 // ↓ 切换到攻击阶段
    │                 isForceAttackAnimation = true  // 上攻击锁
    │                 CutImmediatelyForAttack()       // 清轨+复位
    │                 ExecuteAttackAtPosition(target, onAttackHit, () => {
    │                     // 攻击完成，返回原位
    │                     currentMoveTween = transform.DOMove(originalPosition, moveDuration)
    │                         .OnComplete(() => {
    │                             isAnimating = false
    │                             PlayIdleAnimation()
    │                             onComplete.Invoke()
    │                         })
    │                 })
    │             }
    │         })
    │         .OnComplete(() => {
    │             // 或通过 OnComplete 回调完成（备用）
    │             if (!arrivalTriggered) {
    │                 proceedAfterArrive()
    │             }
    │         })
    │
    └─ [等待 Tween 完成] → 下一阶段
```

### 阶段 4b: 远程攻击流程 (Ranged Attack Phase)

```csharp
DND_CharacterAdapter.ExecuteRangedAttack(
    Transform target,
    System.Action onAttackHit,
    System.Action onComplete
)
    │
    ├─ 4b.1 状态检查（同近战）
    │     if (IsTerminalState() || isAnimating) return
    │     isAnimating = true
    │
    ├─ 4b.2 直接执行攻击（无位移）
    │     ExecuteAttackAtPosition(target, onAttackHit, () => {
    │         isAnimating = false
    │         onComplete.Invoke()  // 无需返回原位
    │     })
    │
    └─ [等待动画完成] → 下一阶段
```

### 阶段 5: 统一的攻击执行 (Unified Attack Execution Phase) ✨

```csharp
DND_CharacterAdapter.ExecuteAttackAtPosition(
    Transform target,
    System.Action onAttackHit,
    System.Action onComplete
)
    │
    ├─ 5.1 预处理
    │     isForceAttackAnimation = true      // 上锁（禁止Walk/Idle覆盖）
    │     CutImmediatelyForAttack()          // 清所有轨道 + 复位骨架
    │         └─ AnimationState.ClearTracks()
    │         └─ Skeleton.SetToSetupPose()
    │         └─ AnimationState.Apply() + UpdateWorldTransform()
    │
    ├─ 5.2 播放攻击动画
    │     PlayAttackAnimation()
    │         └─ string attackAnimName = FindBestAttackAnimationName()
vvv    │         └─ PlayAnimation(attackAnimName, loop: false)
    │             └─ SkeletonAnimation.SetAnimation(attackAnimName, false)
    │             └─ AnimationState.Apply()
    │             └─ Update(0f)  // 立即刷新渲染
    │
    ├─ 5.3 获取动画时长
    │     float attackAnimationDuration = GetAnimationDuration(attackAnimName)
    │     // 读取Spine动画的实际时长
    │
    ├─ 5.4 设置攻击命中回调
    │     DOVirtual.DelayedCall(visualDelay: 0.03f, () => {
    │         // 3. 设置备用触发器（防止Spine事件丢失）
    │         DOVirtual.DelayedCall(
    │             attackAnimationDuration * 0.5f,  // 通常动画50%处
    │             () => {
    │                 if (!hasAttackHitTriggered) {
    │                     hasAttackHitTriggered = true
    │                     onAttackHit.Invoke()  // ← 触发伤害结算
    │                 }
    │             }
    │         )
    │     })
    │
    ├─ 5.5 绑定Spine事件监听
    │     OnAttackHit += tempAttackHitCallback = () => {
    │         if (!hasAttackHitTriggered) {
    │             hasAttackHitTriggered = true
    │             onAttackHit.Invoke()  // ← 触发伤害结算（主路径）
    │         }
    │     }
    │
    ├─ 5.6 设置攻击完成回调
    │     tempAnimCompleteCallback = () => {
    │         if (!hasAttackCompleteTriggered) {
    │             hasAttackCompleteTriggered = true
    │             isForceAttackAnimation = false  // 解除锁
    │             onComplete.Invoke()  // ← 触发后续流程
    │         }
    │     }
    │     OnAnimationComplete += tempAnimCompleteCallback
    │
    ├─ 5.7 备用完成触发器
    │     DOVirtual.DelayedCall(
    │         attackAnimationDuration + 0.1f,
    │         () => {
    │             if (!hasAttackCompleteTriggered) {
    │                 tempAnimCompleteCallback.Invoke()
    │             }
    │         }
    │     )
    │
    └─ [等待Spine事件或定时器触发] → 5.8 & 5.9
```

### 阶段 6: 伤害结算 (Damage Resolution Phase) ✨

```csharp
AutoBattleAI.ProcessAttackHit(
    CharacterStats attacker,
    CharacterStats target,
    bool isMeleeAttack
)
    │
    ├─ 6.1 检查目标特殊状态
    │     int advantageFlag = 0
    │     if (target.HasStatusEffect(StatusEffectType.Unconscious)) {
    │         advantageFlag = isMeleeAttack ? 1 : -1
    │         // 近战优势掷骰，远程劣势掷骰
    │     }
    │
    ├─ 6.2 调用战斗规则系统 ✨ 核心掷骰
    │     var attackResult = HorizontalCombatRules.ResolveAttack(
    │         attacker,
    │         target,
    │         advantageFlag,
    │         isMeleeAttack
    │     )
    │
    └─ 6.3 根据结果处理伤害

             bool isCritical = attackResult.isCritical

         }
```

### 阶段 6.2: 攻击结算规则 (Attack Resolution Rules)

```csharp
HorizontalCombatRules.ResolveAttack(
    CharacterStats attacker,
    CharacterStats target,
    int advantageFlag,
    bool isMeleeAttack
)
    │
    ├─ 6.2.1 确定攻击属性
    │     bool isSpell = attacker.template.defaultAttackType == Spell
    │     var weapon = isSpell ? null : FindEquippedWeapon(attacker)
    │
    ├─ 6.2.2 计算攻击加值
    │     int attackBonus = GetAttackBonus(attacker, isMeleeAttack, weapon)
    │     // 基于武器+属性修正+熟练加值
    │
    ├─ 6.2.3 执行掷骰 ✨ 关键！
    │     int roll1 = Random.Range(1, 21)         // d20
    │     int roll2 = Random.Range(1, 21)         // 若有优势/劣势
    │     int d20 = (advantageFlag > 0)
    │               ? Mathf.Max(roll1, roll2)     // 优势: 取最大
    │               : (advantageFlag < 0)
    │                 ? Mathf.Min(roll1, roll2)   // 劣势: 取最小
    │                 : roll1                      // 正常: 单骰
    │
    ├─ 6.2.4 暴击判定
    │     bool isCritical = (d20 == 20)
    │
    ├─ 6.2.5 计算总攻击值
    │     int totalAttack = d20 + attackBonus
    │
    ├─ 6.2.6 获取目标AC
    │     int targetAc = target.CurrentArmorClass
    │     // 基于护甲类型 + 敏捷修正 + 盾牌
    │
    ├─ 6.2.7 命中判定 ✨
    │     bool isHit = isCritical || totalAttack >= targetAc
    │
    ├─ 6.2.8 伤害计算（如果命中）
    │     if (isHit) {
    │         int damage = CalculateDamageUnified(
    │             attacker,
    │             isCritical,
    │             isSpell,
    │             hitAbility,
    │             weapon
    │         )
    │         // 骰子投掷: 
    │         // - 暴击时双倍骰子数
    │         // - 加上能力修正
    │         // - 应用抗性/易伤
    │     }
    │
    ├─ 6.2.9 记录日志
    │     GameLog.LogHit(attacker, target, ...)
    │     GameLog.LogDamage(attacker, target, damage, ...)
    │
    └─ 6.2.10 返回结果
         return new AttackResult {
             isHit: true/false,
             damage: intValue,
             isCritical: bool,
             damageType: DamageType,
             description: string
         }
```

## 附录: 2D角色自定义与动画复用系统设计方案

本方案旨在为项目设计一套可扩展的1D角色自定义（捏脸/换装）与动画复用系统。参考了业界成熟的Archetype（原型）设计思路，并与当前项目已有的Spine和ScriptableObject技术栈深度整合，以实现在保证丰富自定义性的同时，最大化动画资源的复用率。

### 0. 核心设计思路

系统核心是 **“骨架原型 (Archetype)”** 与 **“部件化 (Modularization)”**。

*   **骨架原型 (Archetype)**: 定义了一类具有相同骨骼结构和动画逻辑的角色“模板”。例如，“人类男性”、“人类女性”、“兽人”、“精灵”等。同一原型下的所有角色共享同一套骨骼数据和动画集。这是实现动画复用的基石。

*   **部件化 (Modularization)**: 将角色的视觉表现拆分成独立的、可更换的“部件”，如发型、脸部、上衣、裤子、武器等。这些部件作为独立的图片资源，在运行时通过Spine的机制动态地挂载到骨架的指定“插槽”（Slot）上。

### 1. 技术选型与整合

继续沿用并深化 **Spine** 的使用，其功能完美支持本方案：

*   **骨骼 (Bones)**: 构成角色的基本骨架。**每个Archetype对应一套固定的骨骼结构**。
*   **插槽 (Slots)**: 挂载“部件”的接口。每个插槽可以控制其上附件的显示/隐藏、颜色、绘制顺序等。例如，`hair_slot`, `weapon_slot`, `head_slot`。
*   **附件 (Attachments)**: 即具体的“部件”图片。例如，“长发”、“短发、“铁剑”、“木弓”。这些是美术制作的独立资源。
*   **皮肤 (Skins)**: Spine的皮肤功能可以用来组织一套完整的“外观方案”。我们可以利用它来管理角色的默认外观或预设套装，并通过代码在运行时混合、匹配来自不同皮肤的附件。

### 2. 实现流程与细节

#### 2.1. 资源制作流程 (美术/动画)

0.  **定义骨架原型 (Archetype)**:
    *   为每个原型（如“人类男性”）创建一套标准的骨架模板 (`human_male_skeleton.json`)。
    *   该模板需包含所有必要的骨骼和插槽，例如：`head`, `torso`, `arm_l`, `hand_r`, `weapon_hand_r` (用于挂载武器) 等。
    *   **注意**: 一旦原型被用于制作动画，其骨骼结构（骨骼名称、层级关系）就不应再轻易改动，否则会导致动画不兼容。

1.  **制作部件资源**:
    *   美术根据骨架原型，绘制各个可更换的部件（发型、服装、武器等）。
    *   每个部件都需要与骨架的特定插槽对齐。例如，所有的发型部件都应与`hair_slot`的位置和尺寸匹配。
    *   将这些部件导入Spine，作为附件放入对应的插槽中。可以为每个部件创建一个单独的皮肤，方便管理。

2.  **制作动画**:
    *   动画师基于**不带任何具体外观附件**的骨架原型进行动画制作（如跑动、攻击、施法）。
    *   由于动画是针对骨骼本身，因此它与最终角色穿什么、长什么样无关，实现了动画的通用性。

#### 2.2. 数据结构设计 (程序)

为了在Unity中管理和应用这些自定义部件，我们设计一套基于 `ScriptableObject` 的数据结构。

0.  **`Archetype_SO.asset`**
    *   **作用**: 定义一个骨架原型。
    *   **字段**:
        *   `archetypeID`: (string/enum) 原型唯一标识，如 `HUMAN_MALE`。
        *   `skeletonDataAsset`: (Spine SkeletonData Asset) 指向此原型对应的Spine骨架数据。
        *   `animationConfig`: (CharacterAnimationConfig) 引用此原型可用的动画配置SO。

1.  **`CustomizationPart_SO.asset`**
    *   **作用**: 定义一个具体的、可更换的部件。
    *   **字段**:
        *   `partID`: (string) 部件唯一ID，如 `hair_long_blonde`。
        *   `partType`: (enum) 部件类型，如 `Hair`, `Face`, `Torso`, `Weapon`。
        *   `targetSlot`: (string) 此部件需要挂载到的Spine插槽名称，如 `hair_slot`。
        *   `attachmentName`: (string) 此部件在Spine文件中的附件名称。
        *   `icon`: (Sprite) 用于在UI中显示的图标。

2.  **`CharacterRecipe.cs`**
    *   **作用**: 描述一个角色的完整外观配置。这是一个普通C#类，用于运行时数据传递和存档。
    *   **字段**:
        *   `archetypeID`: (string/enum) 使用的骨架原型。
        *   `parts`: (Dictionary<PartType, string>) 一个字典，存储了每个部件类型（`PartType`）对应的部件ID（`partID`）。

#### 2.3. 运行时逻辑 (程序)

0.  **角色生成与组装**:
    *   在 `HorizontalBattleFormationManager.CreatePlayerCharacter()` 或类似方法中，传入 `CharacterRecipe`。
    *   根据 `archetypeID`，加载并实例化对应的骨架原型，创建一个`SkeletonAnimation`游戏对象。
    *   创建一个临时的Spine `Skin` 对象。
    *   遍历 `CharacterRecipe` 中的 `parts` 字典。
    *   对于每一个部件，通过 `partID` 找到对应的 `CustomizationPart_SO`。
    *   使用Spine API，将 `attachmentName` 指定的附件添加到我们临时的 `Skin` 中，并关联到 `targetSlot`。
    *   `skin.SetAttachment(skeleton.FindSlotIndex(part.targetSlot), part.attachmentName, skeleton.Data.FindAttachment(part.attachmentName));`
    *   所有部件添加完毕后，将这个动态生成的 `Skin` 应用到角色上。
    *   `skeleton.SetSkin(skin);`
    *   `skeleton.SetSlotsToSetupPose();`

1.  **武器挂载**:
    *   武器是一个特殊的部件。除了应用附件外，通常还需要在武器骨骼（如`weapon_hand_r`下的一个特效点）上挂载额外的特效、碰撞体等游戏逻辑对象。
    *   可以使用Spine的 `BoneFollower` 组件来实现这一点，让Unity中的GameObject跟随骨骼运动。

2.  **动画播放**:
    *   动画播放逻辑与现有系统保持一致。`DND_CharacterAdapter` 继续负责播放动画。由于所有使用该原型的角色骨架都一样，动画可以完美匹配。

### 3. 注意事项

*   **绘制顺序 (Draw Order)**: 需要精心管理插槽的绘制顺序，以确保部件能被正确地遮挡（如头发在脸前，衣服在身体前）。Spine编辑器和运行时API都提供了控制绘制顺序的功能。
*   **性能**: 在单个角色上混合大量部件可能会对批处理（Batching）产生影响。对于需要大量同屏角色的场景，可以考虑将一套常用的外观组合“烘焙”成单个Spine皮肤，以优化渲染性能。
*   **UI与数据**: 捏脸/换装界面的UI需要与 `CustomizationPart_SO` 数据库联动，动态展示可用的部件图标。当玩家选择一个部件时，实时更新预览角色，并在最终确认时生成 `CharacterRecipe` 数据用于保存。
*   **扩展性**: 此结构易于扩展。未来若要添加新的种族，只需制作新的 `Archetype_SO` 和对应的部件资源。若要添加新的服装，只需制作新的 `CustomizationPart_SO` 并确保它们遵循现有原型的规范即可。
*   **武器与动画**: 某些动画可能需要根据武器类型产生变化（如持剑攻击和持弓射击）。这可以通过在 `DND_CharacterAdapter` 中，根据当前装备的武器类型（可从 `CharacterEquipment` 获取），在 `FindBestAttackAnimationName()` 方法里选择播放不同的动画名称（如 `attack_sword` 或 `attack_bow`）来实现。

### 附录B: 核心实践问答 (Q&A) - 动画制作与武器挂载

**问：采用此方案后，Spine动画的制作流程和武器挂载的具体方式是怎样的？**

**答：** 流程的核心是“分离”与“动态组合”，具体如下：

0.  **动画制作在“裸”骨架上进行**：
    *   动画师应针对每个 Archetype (如“人类男性”) 的基础骨架制作一套通用的动画（`attack`, `walk`, `hit` 等）。
    *   这个基础骨架不包含任何特定的服装或武器。这确保了动画的泛用性，可以适配后续任意的换装组合。

1.  **预留专用的武器挂点 (Weapon Point)**：
    *   在 Spine 的骨架上，必须创建一个专门的骨骼（Bone），例如命名为 `weapon_point` 或 `hand_r_weapon`，作为所有武器的挂载“锚点”。
    *   所有武器资源在制作时，其根部都应与此“锚点”的坐标对齐。

2.  **运行时动态挂载武器**：
    *   游戏运行时，系统会根据角色当前装备的武器，将武器的 Spine 附件（Attachment）动态设置到武器挂点骨骼下的插槽（Slot）中，从而实现视觉上的“手持武器”。
    *   如果武器自身还需要挂载特效（如刀光），可以在 Unity 中使用 `BoneFollower` 组件，让一个包含粒子系统的 GameObject 跟随 `weapon_point` 这个骨骼移动。
